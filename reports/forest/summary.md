## Known bugs from the test suite (23)

- **items › MeshAssetIds only lists current items** — MeshAssetIds still has entries for removed/never-added items
- **items › Studio preview plugin lists current items** — studio-plugin ITEM_NAMES predates the #88 roster change
- **abilities › every item has an AbilityConfig entry** — Drill (Rare ENGINE) has no ability, so pressing E with it does nothing
- **abilities › every effectKey has a handler in AbilityManager** — these abilities fire, consume their cooldown and do nothing (AbilityManager warns 'No effect handler')
- **abilities › HEAD/TAIL passives are read by game code** — VehicleStats.HEAD_PASSIVES / TAIL_PASSIVES are defined but nothing reads them, so HEAD/TAIL slots are cosmetic
- **biomes › every BiomeConfig hazard type is implemented** — fallingLog / waveFlood / gustZone are configured but no code spawns them
- **audio › every sound has an asset id** — BGM and ambience ids in SoundConfig are still empty placeholders
- **farming rules › a steal never pushes the thief past the 8-slot inventory** — RequestSteal does not check the thief's inventory size, so a full thief ends with 9+ items
- **farming rules › auto-submit puts items in matching slots** — when the crafting timer runs out, items are assigned to BODY/ENGINE/SPECIAL in inventory order regardless of type
- **FOREST map during RACING › trigger volumes stay non-collidable when the track is shown** — MapVisibility restores CanCollide with `stored ~= nil and stored or true`, which turns every false into true: checkpoints, finish line, drift corners and jump zones become invisible solid boxes
- **FOREST map during RACING › walls never cut into the lane** — walls are one straight box per segment; at sharp kinks the next segment's wall slices into the current lane
- **FOREST map during RACING › off-track slow zones never cover the lane** — SlowZone pads are placed per segment just outside its walls; at sharp kinks they overlap the next segment's lane, so cars on the racing line get the 0.6× off-track penalty
- **FOREST map during RACING › checkpoint triggers span the whole corridor** — checkpoint boxes are axis-aligned 40×6; CP1 sits where the track runs along X, so it covers only a 6-stud strip of the lane
- **FOREST map during RACING › jump ramps sit inside the corridor and face the direction of travel** — JumpRamp_1 is placed 18 studs off the centerline of a 40-wide lane and is not aligned with the track
- **FOREST map during RACING › no tree trunk stands inside the corridor** — tree placement only keeps 35 studs from track NODES, not from the segments between them, so trees grow inside long straights (solid during RACING because of the CanCollide bug)
- **race progress (FOREST) › progress never decreases while driving forward along the track** — progress is zStart - z; the figure-3 layout runs sideways and backwards in Z, so live ranks flip mid-race
- **race progress (FOREST) › the respawn target is on the track everywhere** — respawn always teleports to X = 0; wherever the track is not at X = 0 the car lands on grass outside the walls
- **RacingManager speed effects (real script) › overlapping obstacle + mud returns to the base MaxSpeed** — each effect saves MaxSpeed and restores its saved copy later; bump → enter mud → bump restore → leave mud leaves the car at 2× its MaxSpeed for the rest of the race
- **RacingManager speed effects (real script) › boost during a boost pad returns to the base MaxSpeed** — pad saves base and sets 1.4×; boost saves 1.4× and sets 2.1×; pad restores base after 2 s; a boost longer than 2 s then restores 1.4× permanently
- **race sim (FOREST, median car) › an average driver finishes inside the race timeout on the authored map** — the S5 chicane (N24 −105°, N27 +118°) is a wall pocket: cars stall there and respawning 30 studs back re-enters it
- **race sim (FOREST, median car) › drivers get past the S2 hairpin on the map as shipped** — DriftCorner_1 (40×5×40 at the S2 apex) becomes a solid invisible block during RACING; every run stalls at s≈580
- **vehicle stats (FOREST) › stability changes how fast the car turns** — TurnSpeed = clamp(stability * 0.3, 0.5, 3) hits the 3.0 cap for every build, so BODY grip/weight never changes handling
- **vehicle stats (FOREST) › the acceleration stat affects driving** — VehicleSeat.Torque is derived from acceleration but the drive code sets velocity directly and never reads it
